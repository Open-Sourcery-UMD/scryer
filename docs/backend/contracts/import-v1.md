# Headless import contract v1

`extractBankCsv(bytes, metadata, mapping)` accepts copied `Uint8Array` bytes, `accountRefId`, caller-supplied `observedAt` UTC, and an explicit column mapping. It uses only local Web APIs. The mapping names one ISO `YYYY-MM-DD` date column and either one signed amount column (`positive=credit`, `negative=debit`) or separate credit/debit columns. Exactly one convention is selected; unknown columns, duplicate headers, ambiguous two-sided amounts, invalid UTF-8, malformed CSV, and over-limit inputs return stable typed errors or row warnings without approving history. Filename and MIME detection are advisory only and have no role in value interpretation. The extractor does not infer coverage from transaction dates.

Input limits: 20 MiB raw bytes; 100,000 data records; 256 columns; 64 KiB UTF-8 bytes per decoded field; and 1,000,000 total decoded cells. The composite cell cap is a deliberate lower resource limit: a 20 MiB file can contain millions of tiny comma-separated cells and cause disproportionate array allocation even while meeting each individual cap. A preflight checks CSV quote grammar and counts before the parser allocates rows. A leading UTF-8 BOM and LF or CRLF line endings are supported. Embedded newlines, commas, and escaped quotes in quoted fields are preserved. Bare CR, NUL, unclosed quotes, quote in an unquoted field, and content after a closing quote fail typed. Header names must be nonempty and unique after exact decoding; no case folding or trimming changes identity. Rows must have the header's field count.

The returned batch retains a local copy of `sourceBytes` and the selected mapping for review-time re-extraction; neither belongs in a sync request. Its `artifact` has `kind:"bank_transactions"`, an account binding, raw-byte SHA-256, and explicit observation time. Its opaque ID is deterministic from the account reference and raw digest. A `proposal` preserves the exact raw amount string, source location `row:N:col:M` (logical CSV record index, counting the header as record 1), parser/mapping versions, and nullable proposed nonnegative cents. The proposal ID is deterministic from artifact identity and row position. Each `candidate` retains the row's raw fields locally, exact source position, parsed ISO date or null, `credit`/`debit`/`unresolved`, and stable warning codes. Zero, invalid, and debit amounts do not become approved bank-credit candidates. A proposal is evidence only; its existence has no effect on projections. No part of the raw file or raw row is sent to an application server.

`reviewImport(case, ledger, batch, decisions, command, validateCase)` is a separate operation. `ImportLedger` is `{schemaVersion:"1",reviews:ImportReview[]}`; each review stores artifact ID/digest/account, command ID, recorded time, base head, all decisions in proposal-ID order, and a SHA-256 decision digest. The ledger is local financial metadata and must be encrypted with the case in M6. The case schema alone cannot record `reject` or `exclude`, so case and ledger are one atomic return value and later one local storage transaction.

The review operation requires one explicit `approve`, `edit`, `reject`, or `exclude` decision per proposal. An approved decision supplies unique `factId`, `eventId`, and `reviewId`; `approve` uses exactly the proposed cents, while `edit` supplies explicit positive canonical cents and preserves the original proposal. A rejected/excluded decision supplies no fact/event IDs. Only a positive credit candidate with a valid source date can be approved. Command fields are exact `commandId`, `recordedAt` UTC, and `baseHead` (one current maximal head or null for a case without events). If the case has divergent heads or the selected base is stale, review fails typed instead of silently merging branches. Multiple approvals chain from the base head in proposal order. No clock, random ID, parser guess, or implicit coverage assertion enters the command.

Before accepting decisions, review repeats extraction from the batch's copied bytes and mapping and checks every artifact, proposal, and candidate field. A mismatched raw amount, source position, digest, or parsed direction fails `INVALID_BATCH`. This is internal consistency, not proof of external document authenticity. The complete next case is constructed in memory and passed to the mandatory `validateCase` callback, which must call the production native/WASM case validator before persistence. The operation returns `{case,ledger,applied:true}` only if all decisions and validation succeed. It adds one artifact and its proposals on first import, and only approved/edited `bank_credit_observed` facts become events. An exact repeated reviewed command returns the prior case and ledger with `applied:false` after validation and after checking the prior artifact, proposals, and approved event chain against the ledger. Reuse of the same artifact with a different decision digest fails `IMPORT_CONFLICT`; an artifact in the case without a corresponding ledger record fails `IMPORT_LEDGER_MISSING`. Similar rows from a different artifact are surfaced for review and never silently deleted. Storage commits both returned values and the outbox entry in one local transaction in M6.

`detectSource(bytes)` uses only bounded local bytes. A structurally parseable multi-column CSV is eligible for the generic bank mapping flow (`SUPPORTED_CSV`, `MAPPING_REQUIRED`), not deemed a valid bank statement. Every PDF returns `MANUAL_REQUIRED`, `PDF_LAYOUT_UNVERIFIED`; the detector does not inspect PDF encryption, pages, text, or external resources, so it cannot distinguish scanned, encrypted, corrupt, and textual PDFs. Invalid or over-limit non-PDF input returns `UNSUPPORTED_INPUT` with a typed reason. A filename, MIME type, or recognizable university branding never raises support status.

`manualFact(case, reviewedInput, validateCase)` accepts explicit positive canonical cents, UTC review time, nullable source date, one current head, stable IDs, and a manual source entry marker. Supported roles are `school_credit`, `school_charge`, `refund_issued`, and `bank_credit_observed`; school and refund facts name a term, bank facts do not, and refunds require an explicit broad recipient category. These facts are `USER_ASSERTED` evidence, without an uploaded-source or institution-authenticity claim. `manualCorrection` appends a distinct reviewed event with explicit replacement cents or cancellation and a new manual source marker. It directly parents the original approval plus the current head when they differ, preserving native correction causality. Both commands clone inputs, validate the existing and proposed complete case, and return only after the mandatory production validator succeeds. They do not persist anything; encrypted atomic local storage remains M6. A failed command leaves the caller's case unchanged.

UMD aid-offer, bill, and refund-notice adapters cannot claim compatibility until permitted representative format evidence is recorded. Their compatibility is `BLOCKED_EXTERNAL`; generic manual fact entry is an explicitly limited continuation, not a verified parse. Detailed PDF diagnostics and real-browser worker/cancellation remain open. The browser file/worker boundary must copy bytes, preserve cancellation, and never commit a partial import; this remains a separate M5/M6 integration gate.
