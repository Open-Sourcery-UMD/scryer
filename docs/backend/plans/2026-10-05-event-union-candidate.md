# M8-6b read-only disjoint approval candidate

**Goal:** Produce a browser-only candidate containing both devices' independently approved facts in the narrow case where the two authenticated branches share identical metadata/review ledgers, each retains every event in a historical base candidate, and their new approvals have distinct identities and sources. The candidate is for explicit human review only. This task does not replace the pending outbox, acknowledge a server revision, or publish ciphertext.

**Hazards:** A shared event ID with changed payload, duplicate fact/review/proposal/source identity, a correction, match decision, or changed metadata can silently double count or erase a choice if unioned. The historical package is a candidate, not byte-level proof of ancestry or server freshness. The pure function therefore refuses these cases, returns only reason codes on refusal, and never claims safe publication. A later atomic publish task must recheck local pending identity and current server head.

**Acceptance:** Add red-green headless tests with complete positive cases that the native C++ validator accepts. The positive case preserves both independent manual approvals, is deterministic under branch/event/member order changes, retains all base events, and does not mutate inputs. Negative cases cover missing/unavailable base, base content divergence, metadata or review divergence, event collision, correction/match branches, and same source or review identity across devices. A Chrome preview also builds the candidate and passes it through the native validator. This narrow path refuses ordinary concurrent imported statements because their metadata or review ledgers differ. Run client typecheck, headless tests, browser build, and relevant browser preview suite. Record limits in the sync contract and requirement/task evidence, then commit this coherent read-only slice.
