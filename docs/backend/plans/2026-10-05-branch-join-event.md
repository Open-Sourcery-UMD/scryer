# M8-6c explicit branch-join knowledge event

**Task ID, parent requirements, and risk:** M8-6c; S-16, S-60, S-69; HIGH. Depends on M8-5c verified historical-base content comparison and M8-6b read-only disjoint approval candidate. Ownership is the case contract, Python and C++ parsers, and the import review-ID preflight. This task establishes the event type; a reviewed browser writer and publication remain later tasks.

**Decision and exact interface:** Add `resolve_branches` to case v1 as an immutable, nonmonetary journal event with exact fields `eventId`, `parents`, `recordedAt`, `kind`, and `resolution`. `kind` is `resolve_branches`; `parents` contains exactly two distinct existing event IDs; `resolution` has exactly `reviewId`, unique among all event review IDs. Update `docs/backend/contracts/case-v1.schema.json`, `scryer_reference/model.py`, `engine/include/scryer/case.hpp`, `engine/src/case.cpp`, `client/import/types.ts`, and `client/import/review.ts`. The two parents are intended to be reviewer-selected heads; the generic parser validates distinct existing parents, while a future writer must validate actual head selection and review authorization.

**Why:** A sorted union of two event arrays has two heads and does not record the user's resolution action. Scryer's historical query and receipt model need a causal event that makes a later one-head snapshot include both histories while preserving both source events. A server revision or device timestamp is not a financial knowledge event.

**Invariants:** The marker changes knowledge ancestry but not any amount, source assertion, correction choice, or match decision. A case with two independent compatible approval branches has one joined current head and a projection containing both. A join over conflicting corrections remains `CONTRADICTORY_EVIDENCE`; an explicit superseding financial decision is still required. Existing import review commands may not reuse its review ID. Missing/duplicate parents, cycles, malformed payload, and duplicate review IDs fail typed. Neither parser proves that two selected parents were incomparable heads. Older parsers reject this event, so a future writer needs a compatibility gate before publication.

**Verification and expected results:** `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests/reference -p 'test_*.py' -q`; `make -C engine test-money test-json test-case test-projection test-receipt test-coverage test-matching test-lifecycle cli`; `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest tests.engine.test_cli -q`; `npm --prefix client run typecheck`; `npm --prefix client test`; and parse the JSON contract. `tests/reference/test_model.py`, `tests/engine/test_case.cpp`, `tests/engine/test_projection.cpp`, and `tests/engine/test_cli.py` cover the join and contradiction. `tests/client/test_review.mjs` first fails when an import reuses the join review ID and then passes after the preflight fix. All tests must pass; no server, outbox, or browser writer is changed in this slice.

**Done for this slice:** The schema and both independent parsers agree on the marker and the focused tests pass. Documentation and traceability identify the compatibility and future writer limits. A subsequent task must require explicit human review, create the join marker in an atomic local transaction, preserve both branches on publish conflict, and demonstrate native/WASM validation before any public release claim.
