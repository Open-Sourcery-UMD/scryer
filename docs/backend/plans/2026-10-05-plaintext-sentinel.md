# M8-6a synthetic plaintext boundary sentinel

**Goal:** Exercise the actual local browser, HTTP API, and PostgreSQL path with an approved synthetic amount and a synthetic source-text sentinel. Prove that the browser retains usable plaintext after decryption while saved requests, HTTP ciphertext responses, and server-owned storage never contain the sentinel as clear UTF-8. This is privacy boundary evidence, not real-data approval or public-service certification.

**Task ID and risk:** M8-6a, HIGH. **Requirements:** S-57, S-59, RC-31. **Depends on:** M6 encrypted repository, M7 ciphertext API, and M8 browser/API/PostgreSQL integration. **Files:** `tests/sync/test_client_integration.mjs`, `tests/sync/_client_api_fixture.py`, `docs/backend/release-corpus.md`, requirement/task ledgers, status, and verification.

**Test design:** Replace the integration journey's empty case with a schema-valid synthetic bank observation and unreviewed source proposal containing a deliberately invalid-real-world sentinel. First assert the browser can reopen the case and see the source sentinel and approved manual bank amount; a test with an empty case must fail this assertion. Repeat both checks after fresh-page recovery and for local, remote, and candidate-base conflict branches. Assert that saved outbox step bodies, the browser encrypted snapshot, observed browser-to-API request bodies across each phase, collected loopback API output, and server-returned current/historical ciphertext lack the sentinel. A separate read-only fixture command scans every text/bytea/JSON column in the disposable `scryer` and `scryer_private` schemas and reports only counts. Require nonzero retained revision and staged rows so a clean scan cannot pass vacuously. Never print the plaintext fixture, credentials, database rows, or ciphertext in test diagnostics.

**Safety:** The test uses only synthetic values, a disposable database, loopback API/Chrome, and existing local dependencies. The fixture command must reject an empty sentinel and must not mutate the database. It returns aggregate counts, not row values. The browser still uses an injected semantic validator and the API uses a unit-only token verifier, so RC-31 remains `PARTIAL` until the production WASM/real-token path is exercised. Deployed logs, backups, telemetry, browser internals, and other storage are outside this local test.

**Verification:** Run the focused integration first with the new local-presence assertion to observe red on the empty case, then complete the synthetic fixture and scan and rerun green. Build the browser client, run the focused Chrome/API/PostgreSQL journey, run the full 85-test sync suite if fixture changes affect it, and request focused review. Commit only the coherent test/evidence slice after staged diff and sensitive-pattern checks.
