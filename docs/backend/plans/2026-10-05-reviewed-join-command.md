# M8-6d reviewed disjoint-approval join command

**Task ID, requirements, and risk:** M8-6d; S-16, S-60, S-69; HIGH. Depends on M8-6b read-only disjoint approval candidate and M8-6c nonmonetary join event. Files: `client/sync/analysis.ts`, `tests/client/test_conflict_analysis.mjs`, `docs/backend/contracts/sync-v1.md`, and traceability/evidence documents.

**Decision:** Provide a pure browser-compatible preparation function. The caller must supply an explicit review command naming the pending operation, pending revision, and manifest digest; local/remote/base revisions; the two selected heads; sorted approved branch-only event IDs; a SHA-256 digest of the complete canonical candidate case and ledger; a fresh event ID; a fresh review ID; and a UTC recorded time. The command is an input from a future review UI; this function cannot prove a human actually inspected the source records. It must not read storage or network, alter the preview, replace the outbox, or publish ciphertext.

**Interface:** `digestDisjointApprovalCandidate(preview): Promise<string>` returns the candidate-content digest only when the conservative union proposal is available. `prepareReviewedApprovalJoin(preview, command, validateCase): Promise<{case, ledger, joinEventId, parentHeads}>` rebuilds the proposal, verifies every command binding against it and the preview, requires exactly two distinct maximal heads that are the named local and remote heads, appends one `resolve_branches` event, and invokes the supplied production case validator. Any refusal returns a stable nonfinancial error code. The returned case is a new in-memory object.

**Invariants:** Existing events and metadata are byte-semantically unchanged. The join adds no fact or amount. The prepared case has one maximal head and the supplied validator accepts it. A changed candidate payload with equal IDs, wrong revision/manifest/operation, changed review inventory, stale or multiple heads, reused event/review ID, malformed command, validator failure, or unavailable/diverged ancestor cannot produce a prepared join. The command digest binds the case and ledger; it does not prove server freshness or ancestry beyond the previously checked candidate content. A future writer must compare live IndexedDB state, make an atomic replacement, and recheck the current server precondition before publication.

**Tests and done:** Build complete native-valid synthetic cases in `tests/client/test_conflict_analysis.mjs`. Observe red tests for the absent functions, then make the positive exact-content join native-valid with one head and unchanged source approvals. Negative tests cover candidate tampering with equal event IDs, wrong command bindings, reused IDs, multiple heads, altered ledger/metadata, unavailable ancestor, and validator rejection with no input mutation. Run focused headless tests, full headless suite, typecheck, browser build, and relevant Chrome analysis test. Document honest limits. This slice is done only for the in-memory command, not local persistence or sync.
