# Synthetic Demo Accessibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify and improve keyboard and assistive access to the account-free synthetic demo.

**Architecture:** Run the production static HTML/CSS in locally installed Chrome through the existing `playwright-core` dependency. Make the two source links unambiguous in the Next.js page. Keep this as a separate browser gate because a normal frontend build should not require an installed browser.

**Tech Stack:** Next.js 16, React 19, Node test runner, Playwright Core 1.63, local Chrome.

**Spec:** `docs/superpowers/specs/2026-10-30-synthetic-demo-accessibility.md`

## Global Constraints

- Synthetic data only; no network, deployment, or GitHub changes.
- A browser accessibility-tree check does not establish actual screen-reader usability.
- Use the production Webpack build artifacts generated by `npm --prefix frontend run build`.

## Review Focus

- A hidden mobile navigation link must not be counted as keyboard reachable.
- The skip link must move focus to content, not merely change the URL hash.
- A collapsed fact row must open with Enter and expose source details.
- Refund and bank records must retain distinct source IDs and approval IDs in the accessibility tree.
- At 320 CSS pixels, both routes must avoid horizontal page overflow.
